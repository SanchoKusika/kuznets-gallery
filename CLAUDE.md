- Документация проекта — в Obsidian: `C:\Users\Sancho\Documents\Obsidian Storage\Проекты\Kuznets Gallery\` (00 Обзор … 11 Каталог и WordPress). После каждого этапа и каждой заметной правки обновлять план (чекбоксы), экраны, компоненты, сверку, решения и статус в обзоре; `README.md` и этот файл — когда меняется то, что в них описано.
- Эталон — прототипы `design/*.dc.html`, спецификация — `design/README.md`. Повторять до пикселя. Соглашения (BEM, без инлайн-стилей, DRY/KISS) — в `README.md`.
- Этап: ветка `stage-N-…` → код → `npx tsc --noEmit`, `npm run lint`, `npm run build` → сверка → PR в `main` → код-ревью плагином → правки → мерж. Правки вне этапов — так же, ветка по смыслу (`admin-photo-editor`). Владелец разрешил мержить PR самостоятельно (squash, `--delete-branch`); этапы не ставить друг на друга.
- Код-ревью — плагином `code-review:code-review`. Замечания ниже порога, если они по делу, всё равно исправлять до мержа и перечислять в комментарии к PR («Follow-ups applied…»). Простые PR (только картинки, тексты, конфиг) плагин пропускает — тогда сразу мерж.
- Сверку с прототипом делать через Claude in Chrome: приложение (`npm run dev`, :3000) и прототип (`npx serve design -l 4000`) рядом, смотреть скриншоты. Экраны сайта и админки сверены и приняты владельцем; у новых функций без прототипа (редактор фото) — только проверка работы в браузере.
- В коммитах и PR не упоминать Claude: ни Co-Authored-By, ни «Generated with».
- Во время работы не писать промежуточных сообщений — только итог в конце.
- Каталог в Supabase — источник правды (сверен с kuznets.uz, `11 Каталог и WordPress`). Скрипты БД — `node --env-file=.env.local scripts/db/…`. После правок прямо в базе сбросить кеш сайта: открыть работу в админке (`/admin?edit=KZ-xxx`) и «Сохранить». В Storage — только файлы, на которые ссылается работа или заявка.
- Если dev-сервер ведёт себя странно (старый код после правки общего модуля), перезапустить `npm run dev`. `npm run build` при работающем dev не запускать — сначала остановить dev (процесс `next dev` может пережить остановку npm: проверить, что порт 3000 свободен).
- Деплой — Vercel (проект `kuznets-gallery` на аккаунте владельца, подключён к GitHub): мерж в `main` выкладывает продакшен — это демо на kuznets-gallery.vercel.app, у PR — превью. Переменные Supabase ставит интеграция Supabase ↔ Vercel; индексируется только kuznets.uz (`src/lib/site-url.ts`); cron в `vercel.json` раз в день обращается к базе, чтобы Supabase не заснул. Прод kuznets.uz — в планах на Cloudflare Workers (Vercel Hobby запрещает коммерческие сайты), код — тег `cloudflare-opennext` (закрытый PR #19); там этот пинг нужен как Cron Trigger. Карта в подвале — Яндекс Карты, ключ `YANDEX_MAPS_KEY` (Vercel, sensitive) ограничен по Referer: `localhost`, `kuznets-gallery.vercel.app`; при переезде на kuznets.uz добавить домен в ключ (или завести ключ галереи), в превью PR карты нет.
- Форматтера в проекте нет — `npx prettier` не запускать (переформатирует файлы под 80 символов).
